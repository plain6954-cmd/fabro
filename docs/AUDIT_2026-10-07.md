# Fabro application audit — 7 October 2026

## Scope and environment

This audit covers the working tree after the Antigravity changes and the fixes in this delivery. The exact authorship boundary of the pre-existing uncommitted changes cannot be proven from Git history. Tests used disposable Django users, an isolated SQLite database, temporary media, and a synthetic `TOYOTA RAV4 2026–2026 BR2` vehicle. The reference production record `/car-details/?vehicle_id=552#design-options` and real accounts were not modified. No production deployment was performed.

Browser: installed Google Chrome 154.0.8037.98, driven headlessly by Playwright on Windows. Viewport tests are browser viewport checks, not physical device or cross-browser certification. The 200% check used an equivalent CSS viewport of 683 × 384 for a 1366 × 768 window; Chrome's actual zoom control was not changed.

## Confirmed defects and changes

| Finding | Root cause and resolution |
| --- | --- |
| Designer upload could appear to hang or report an expired session for a non-authentication failure | The upload path mixed validation, storage, approval creation and error handling, while the frontend treated several unsuccessful responses as an expired login. Uploads now validate the complete batch, report validation/storage/CSRF errors accurately, clear the loading state, and use a client upload key for safe retries. Browser upload, invalid-file and retry journeys pass. This reproduces the symptom in isolation; it does not establish the exact failure that occurred on production vehicle 552. |
| A failed or retried upload could leave inconsistent records or duplicate approvals/notifications | Design creation and review submission now run in one transaction with cleanup of newly written files on failure. Repeated upload keys return the existing image, and initial review submission avoids a second notification. |
| Review cycles could be advanced from stale tabs; decisions without a submitted review could create a matrix | The design row is locked before cycle/decision changes. Resubmission requires the current rejected cycle, resets both reviewer decisions, and uses the same logic for HTML and API routes. CAD and ED remain independent reviewers. |
| Pending design originals and review pages needed consistent visibility | Pending image downloads and approval list/detail now enforce designer ownership, authorized CAD/ED review, or admin access. A role flag alone cannot authorize a CAD/ED decision. A missing 403 template caused denied requests to render a 500 with production-style settings; the template is now present. |
| Pattern Master row controls could also trigger row navigation | Row activation excludes nested controls and touch scrolling, while normal row clicks, keyboard Enter/Space, and visible focus still work. Dynamic folder and image cards are keyboard activatable. |
| Pattern Master made a duplicate initial design-folder request and approval list had an N+1 access path | The duplicate fetch was removed, the latest approval uses prefetched records, and the approval list is paginated. A focused query test went from 12 queries for 12 `latest_approval` accesses to 0 after prefetch. The deep-link page now issues one design-folder list request in the Chrome trace. |
| Storage failure could silently fall back to local public media | The S3 adapter now propagates failure to the caller. The upload endpoint returns a retryable error and does not expose a public local media URL. |
| Vehicle Drive links lacked a repeatable UI and validation path | The per-vehicle link model, migration, add/delete endpoints and Pattern Master controls were retained and tested. Asset managers, including designers, can add HTTPS `drive.google.com` links; deletion remains admin-only. |

## Responsive and performance evidence

The four route/role combinations above passed viewport checks at 320 × 568, 360 × 800, 390 × 844, 568 × 320, 768 × 1024, 1024 × 768, 1366 × 768, 1920 × 1080 and 2560 × 1080, plus the effective 200% viewport. A 390 × 844 touch emulation passed scroll and nested-menu activation. Reduced-motion preference was enabled in the browser contexts. Continuous resizing, actual Chrome 200% zoom, physical touch devices, every modal/drawer, long-content stress data, and non-Chrome browsers remain untested.

CDP traces and PerformanceObserver data were recorded for admin Pattern Master, designer vehicle deep link and CAD approvals. The duplicate folder request decreased from two to one; prefetched latest-approval access decreased from 12 queries to zero. Indicative final-run median navigation timings across the nine viewports (milliseconds):

| Page | Server response start | DOM ready | Load |
| --- | ---: | ---: | ---: |
| Admin Pattern Master | 171 | 344 | 376 |
| Designer Pattern Master | 116 | 223 | 240 |
| CAD design approvals | 71 | 144 | 156 |
| Admin panel | 104 | 198 | 208 |

An earlier run measured 465/760/825 ms for admin Pattern Master and 302/525/593 ms for designer Pattern Master. These runs had different cache and test-process conditions, so their timing differences are observations, not a controlled speedup claim. Final CDP traces still showed variable layout and event tasks; the recorded trace did not expose usable `DrawFrame` events, so it cannot establish frame-drop rates.

## Verification and notification impact

`manage.py check`, migration drift check, and `manage.py test management --settings=scripts.offline_settings --noinput` passed. The final test run completed **306 tests**. Chrome checks used isolated sessions with synthetic users and mocked external push delivery. Storage failure, duplicate retry, rollback, authorization, reviewer routing, resubmission, and push failure are covered by regression tests. Browser push permission prompts, real push delivery, real PostgreSQL/Garage behavior and the production vehicle remain unverified.
